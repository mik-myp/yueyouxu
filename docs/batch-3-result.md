## 阶段 3A：经期事实与日期冲突

已完成：

- 新增 `PeriodRepository`，统一原生 SQLite 与 Web 预览的经期列表、读取、保存和删除接口。
- 新增 `record-period` 用例，支持经期开始、结束和修正日期。
- 开始日期、结束日期统一校验为本地 `YYYY-MM-DD`；结束日期不能早于开始日期。
- 新经期不能与其他已有经期重叠；修改自身记录时允许保留原 ID。
- 结束操作只结束最近一个尚未结束且开始日不晚于结束日的经期。
- 今天页和记录页的经期按钮接入 Repository，不再只修改临时 UI 状态。
- 今天页保留短暂撤销操作：撤销开始会删除新经期，撤销结束会恢复开放经期。
- 初始化创建的第一条开放经期可直接结束，刷新后状态仍从本地事实恢复。

浏览器验收：

- 初始化完成后点击“月经走了”，刷新后按钮变为“月经来了”。
- 再次点击“月经来了”，刷新后按钮恢复“月经走了”。
- Web `localStorage` 中的 `periods` 会分别保存 `endDate` 和 `null`，没有依赖临时状态。

自动化验证：

- `npm run typecheck`：通过。
- `npm run lint`：通过。
- `npm test -- --runInBand`：9 个测试套件、16 个测试通过。

## 阶段 3B：每日记录

- 已实现流量、痛感、症状、心情和备注的暂存、确认、取消与持久化。
- 只有确认会写入 Repository；取消、遮罩关闭和下滑不会修改。
- 空白记录自动删除，不在日历留下错误的“已记录”状态。

## 阶段 3C：日历与修正闭环

- 日历接入实际经期、预测范围、每日记录和当前选择状态。
- 过去的非经期日期采用事件式补录：点击“月经来了”立即保存开放记录，再选择“月经走了”日期关闭当前经期。
- 开放记录只把开始日标记为实际事实，后续按参考经期长度显示预计色带；预计范围不写入事实数据。
- 每组“来了 -> 走了”独立形成一条记录，相邻或间隔很短的多段经期也不自动连接或合并。
- 开放记录不再按无限区间参与开始事件的重叠判断；结束事件形成完整范围时仍会检查是否确实跨越另一段已有经期。
- 当前经期尚未结束时仍可补录更早周期；系统按所选日期匹配最近的开放记录，因此补录历史周期不会要求先结束当前周期。
- 多条开放记录各自生成预计色带，并在下一条经期开始日前截断；为历史记录选择“月经走了”不会修改更晚的开放记录。
- 移除“用所选日期修正最近经期”入口；已有经期只能先选中对应日期，再进入“调整经期”，避免把任意日期误用于最近记录。
- 经期开始日、结束日和删除操作统一采用“选择操作后确认”的交互。
- 修正和删除会刷新首页、记录页、预测与趋势；刷新或重启后从本地事实恢复。
