# v0.1 开发计划

更新日期：2026-09-01

状态：已确认

## 执行原则

- v0.1 分批开发，每次只执行一个批次。
- 每批必须形成可独立运行和验收的结果，不提前混入下一批功能。
- 每批结束后检查运行结果、测试、截图和变更范围，再决定是否调整后续计划。
- 当前批次通过后才进入下一批，避免架构、布局或交互问题扩散。
- AI、暗色模式、备孕、易孕期等非 v0.1 功能不得作为“顺便实现”的内容加入。

## 批次 0：工程基线

### 范围

- 初始化 Expo + React Native + TypeScript 项目。
- 配置 Expo Router、Restyle、代码检查、格式化和测试框架。
- 验证 SQLite、日历、SVG、动画、手势和底部面板候选依赖的版本兼容性。
- 确认 Expo Go 或 Development Build 的开发方式。
- 建立与领域、数据和页面边界一致的目录结构。

### 验收

- iOS 和 Android 配置可被 Expo 工具识别。
- TypeScript、Lint 和测试命令通过。
- 候选原生依赖通过 Expo 依赖检查。
- 项目只包含应用外壳，不包含后续批次业务实现。

## 批次 1：可调整 UI 原型

### 范围

- 建立 Restyle 主题、设计令牌和基础组件。
- 实现 `今天`、`记录`、`趋势` 三标签导航及设置入口。
- 使用固定模拟数据实现今天页、记录页、趋势页和设置页布局。
- 实现记录详情底部面板及不同记录类型的交互原型。
- 使用多尺寸 iOS、Android 截图检查布局、文字和触控区域。

### 验收

- 确认色彩、间距、日历高度、记录顺序和面板交互。
- UI 调整不依赖数据库和预测算法。

## 批次 2：数据基础与首次设置

### 范围

- 建立 SQLite 迁移、领域模型和 Repository。
- 实现周期基础设置、首次设置流程和本地恢复。
- 确立本地日期、创建时间和时区的保存规则。
- 覆盖数据库初始化、迁移、读取和清除测试。

### 验收

- App 重启后基础设置仍能恢复。
- 数据层不依赖 React Native 页面。
- 数据表和领域模型经审核后冻结为 v0.1 基线。

## 批次 3：完整记录流程

### 范围

- 实现经期开始、结束和日期修正。
- 实现流量、痛感、症状、心情和备注记录。
- 在日历展示实际经期和每日记录状态。
- 实现单选立即保存、多选实时保存和撤销。
- 处理日期冲突和 App 重启后的状态恢复。

### 验收

- 从选择日期到完成常用记录不超过 10 秒。
- 所有事实记录正确持久化并可修改。

## 批次 4：确定性预测与首页

### 范围

- 根据完整经期记录重建周期。
- 样本不足时使用用户设置的默认值。
- 样本足够时计算稳健的预测日期范围和置信等级。
- 历史修改后使旧预测失效并重新计算。
- 首页周期弧和日历预测标记接入真实结果。

### 验收

- 固定数据覆盖规则、跨月、缺失和异常长短周期。
- 实际记录与预测在数据和视觉上严格分离。
- 预测文案不表达为医疗结论或单日承诺。

## 批次 5：趋势与隐私闭环

### 范围

- 实现周期长度、经期长度、波动范围和历史经期列表。
- 实现数据不足、空状态、加载和操作错误状态。
- 完成周期设置、隐私信息和清除全部本地数据。
- 验证核心功能完全离线可用。

### 验收

- 产品简报列出的 v0.1 功能形成完整闭环。
- 清除数据后不残留事实记录和派生结果。

## 批次 6：发布前加固

### 范围

- 检查 iOS、Android 多尺寸真机布局。
- 覆盖月末、年末、闰年、跨时区和系统日期变化。
- 检查键盘、安全区、底部面板和长文本。
- 完成无障碍、性能、迁移、崩溃恢复和构建验证。

### 验收

- 所有 v0.1 自动检查和人工验收项通过。
- 形成可分发测试的 v0.1 候选版本。

## 批次决策点

- 批次 0：确认 Expo Go 或 Development Build，以及 SQLite 数据访问方案。
- 批次 3 前：确认历史经期允许修正的粒度。
- 批次 4 前：确认预测范围和置信等级的计算口径。
- 批次 5 前：确认趋势指标的定义和展示口径。

## Git 工作流

每个批次使用独立分支，分支在开发开始前创建：

1. 确认本地 `master` 与远端同步。
2. 从 `master` 创建 `batch/<编号>-<名称>` 分支。
3. 只在该分支实现当前批次。
4. 完成当前批次的测试、检查和人工验收。
5. 提交当前批次并推送分支到远端。
6. 使用非快进合并将批次分支合并到 `master`，保留明确的合并节点。
7. 推送远端 `master`，然后才允许创建下一批分支。

批次分支推送后保留在远端，不自动删除。需要回滚时优先对对应合并提交执行 `git revert`，不改写已经推送的公共历史。未经明确要求不使用强制推送。
