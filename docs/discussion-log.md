# 讨论记录

## 2026-09-01

### 已确认

- 产品聚焦经期记录、周期预测和趋势分析。
- 不包含健康内容、社区交流和电商。
- 技术路线为 Expo + React Native + Restyle。
- 产品要求美观但清醒、操作简单、本地优先。
- 每次记录都应成为本地算法的分析数据源。
- AI 分析可选，允许用户配置兼容 OpenAI 协议的 `baseURL` 和 API Key。
- v0.1 只实现首次设置、经期和基础每日记录、日历、本地预测、基础趋势及本地存储组成的离线基础闭环。
- v0.1 不包含备孕模式、易孕期或排卵预测、暗色模式、AI、账户同步、通知提醒、数据导入/导出、小组件和健康平台接入。
- AI 分析和服务配置推迟到离线基础功能稳定后的版本。
- 底部主导航采用 `今天`、`记录` 和 `趋势` 三个入口，设置从右上角进入。
- 记录页采用上方月历、下方所选日期记录列表的上下结构。
- 点击记录项目后从底部展开详细字段；单选立即保存，多选实时保存。
- v0.1 的记录项目确认为经期状态、流量、痛感、症状、心情和备注，具体选项记录在 UI 布局规范中。
- v0.1 分为工程基线、UI 原型、数据基础、记录闭环、预测、趋势与隐私、发布前加固七个批次。
- 每次只执行一个批次，当前批次验收完成后才进入下一批。
- 每批在开发前从 `master` 创建独立分支；完成后提交并推送分支，再以非快进方式合并和推送 `master`。
- 远端保留批次分支；已推送历史通过 `git revert` 回滚，不使用强制推送改写历史。
- 批次 0 采用 Expo SDK 57、React Native 0.86、React 19 和 TypeScript 6。
- v0.1 开发阶段使用 Expo Go；只有出现不受支持的原生模块时才切换 Development Build。
- SQL 层采用 Drizzle ORM，并通过 Repository 隔离页面、领域层和具体数据库操作。
- iOS 和 Android 是 v0.1 产品目标；SQLite Web 仍为 alpha，Web 仅作为开发辅助平台。
- 批次 1 已完成 `今天`、`记录`、`趋势`、`设置` 页面和三标签导航的可调整 UI 原型。
- 批次 1 的实际经期使用连续实色带，预测经期使用描边色带；月份头和星期标题使用中文。
- 记录详情使用底部面板；流量、痛感和心情单选后关闭，症状支持面板内多选，备注完成后保存。
- 批次 1 所有数据与交互状态仅存在内存中，刷新后重置；页面间尚未共享记录状态。
- UI 主色仍使用柔和经期粉色，辅助文字和操作色已调整到 WCAG AA 对比度。
- Web 端备注输入使用标准 React Native `TextInput`，避免 Gorhom Bottom Sheet 与 React Native Web 0.86 的焦点 API 兼容问题；移动端继续使用 `BottomSheetTextInput`。

### 设计方向

- 参考美柚的柔和气质、粉色经期语义、日历高亮和图标化快速记录。
- 不复制美柚品牌资源，不继承其信息流、社区和营销型首页。
- 以“周期弧”作为首页主要视觉，其余界面保持克制和清晰。
- 日历不使用装饰卡片，记录区采用带分隔线的统一列表，不堆叠独立卡片。
- 实际记录、算法预测和 AI 解读必须具有不同视觉与文案身份。
- WebView 方案的推荐视觉方向命名为 `Soft Companion`，整体控制为 70% 成熟清晰、20% 柔软黏土触感和 10% 卡通插画与微动画。
- 以 Better Design 的 `Sorbet` 作为柔和日历和粉彩状态的主要视觉参考，以 `Cashmere` 提高成年感和长期耐看度，以 `1st-Pouf` 提供快速记录控件的局部按压感。
- 卡通插画仅用于首次引导、空状态、保存成功和少量反馈，不持续占据日历、记录和趋势等核心界面。
- shadcn/ui 只作为行为、可访问性和源码基础；项目将维护自己的语义令牌、领域组件和私有 Registry，不直接套用默认 SaaS 外观或外部完整主题。
- 不采用 NeoBrutalism 或 8bitcn 作为主界面风格，也不混装多套外部主题。
- 已确认现有 Expo + React Native + Restyle 能实现 `Soft Companion`；shadcn Registry 的源码不能直接复用，但其视觉语言可由 Restyle、React Native 样式、SVG、Reanimated 和原生底部面板复现。
- `Sorbet`、`Cashmere` 与 `Soft Pouf` 不再作为三套互斥方案：Sorbet 负责日历和柔和状态色，Cashmere 负责成熟结构，Soft Pouf 只负责记录控件和导航选中态的局部触感。
- 新增独立的 `批次 1.5：Soft Companion 视觉验证`，只改造记录页、一个记录详情底部面板和底部导航，沿用固定模拟数据，不接触 SQLite、Repository、领域模型、预测或持久化状态。
- 视觉验证必须覆盖 iOS 与 Android 真机、安全区、短屏、底部面板手势与键盘、中文文本、触控区、双平台阴影和减少动态效果。
- 只有真机验收通过并由用户明确确认后，才把该视觉推广到今天页、趋势页、设置页、首次设置和状态页；否则先调整复验或放弃。
- 批次 1.5 已在 `batch/1.5-soft-companion-visual-validation` 分支完成代码实现：记录页、症状面板和自定义底部导航使用 `Soft Companion`，其他页面内容与数据层未改造。
- Phosphor 仅通过项目 `soft-icons` 边界按图标路径引入，避免 Metro 将整套图标打包；Lucide 暂时保留给本批次范围外的页面。
- 浏览器移动尺寸、标签切换、症状多选、非经期日期、减少动态效果和 WCAG A/AA 自动检查已通过；阴影、连续圆角、底部面板手感和安全区作为真机验收关注项记录在批次结果中。
- 用户已确认批次 1.5 的 `Soft Companion` 视觉方向“通过”；`Sorbet + Cashmere + Soft Pouf` 成为后续页面可采用的视觉基线，但推广必须进入对应后续批次。
- 批次 2 前新增 `批次 1.6：Soft Companion 全局视觉推广`，将已验证的视觉基线推广到今天、趋势、设置、共享组件及全部记录面板，不修改数据层和记录语义。
- 全局推广继续保持 70% 成熟清晰、20% 柔软触感、10% 克制反馈；首页周期轨道是唯一强视觉记忆点，普通信息区不做卡片堆叠。

- 所有记录面板统一使用左上角取消、右上角确认；面板内修改先暂存，只有确认才写入，其他关闭方式均放弃修改。

- 首次初始化只要求最近一次经期开始日期；初始周期长度和经期长度为可选参考值，默认分别为 28 天和 5 天，不收集姓名、年龄及其他无关健康资料。

### 架构提案

- 使用 SQLite 保存事实记录，分析结果采用可删除、可重算的版本化快照。
- 本地算法先完成预测和趋势，AI 只解释结构化结果。
- 用户 API Key 存入 SecureStore，不进入 SQLite 或日志。
- AI 调用前展示数据发送摘要，默认不发送备注原文。
- AI 功能的首个版本优先兼容 Chat Completions；Responses API 作为独立协议适配器评估。
- 如果正式切换到 WebView，优先采用 `Capacitor + React + Vite + TypeScript + shadcn/ui + Tailwind CSS v4`，不建议把全屏 WebView 长期嵌入 Expo。
- WebView 技术路线需要先用记录页原型验证 Calendar、Drawer、软键盘、返回手势、离线存储和 iOS/Android 真机表现，再替换当前 Expo + React Native + Restyle 架构。
- 外部 shadcn Registry 不安装包含数百组件的整套 `all`；按需审查并引入组件源码，统一为项目设计令牌和移动端规范。

## 2026-09-02

### 历史经期补录修正

- 经期记录最终确认为用户事件模型：“月经来了”立即保存开始事件，“月经走了”保存结束事件并关闭对应经期。
- 开放经期只把开始日视为实际事实，后续参考天数属于预计状态，不能作为用户已经确认的实际经期。
- 多次“来了 -> 走了”分别形成独立记录，不因为日期接近而连接或合并；例如 1～2 日与 4～6 日保留为两段，3 日为空白。
- 开放经期不再被当作延续到无限未来，因此可以在已有后续记录前补录开始事件；结束事件如果确实跨越另一段经期仍会被阻止。
- 已有经期不再通过“最近经期”快捷入口修正，必须从对应日期进入调整，降低误修改风险。
- 初始化记录尚未确定结束日时，不限制用户补录更早周期；例如 `9 月 1 日`保持开放时，可以补录`8 月 1 日来了 -> 8 月 2 日走了`。
- 开放记录按日期归属而不是全局唯一：结束操作只关闭开始日不晚于所选日期的最近开放记录，后续开放记录保持不变。
- 若所选日期之前已有开放记录，则该日期继续表达“月经走了”，避免在同一时间线上重复开始；结束范围跨越另一段事实记录时仍拒绝保存。

### v0.1 确定性分析调整

- v0.1 不实现 AI 分析、服务配置或可见状态，已有界面入口和预先设计的提供商方案从当前产品与架构文档移除；早期讨论保留为历史记录，不代表当前实现。
- 每日观察只保留流量、痛感和症状；心情受多种周期外因素影响，备注属于非结构化敏感文本，两者不进入 v0.1 数据模型。
- 用户保存的每段经期始终作为事实独立展示；预测算法只筛选周期间隔，不能合并、删除或改写事实。
- 周期分析使用最近最多 12 个 10～90 天有效间隔的中位数；少于 10 天的开始事件不改变当前分析锚点，超过 90 天的间隔建立新的分析锚点。
- 波动使用中位绝对偏差，预测置信度同时取决于有效样本数和个人波动；只有一个间隔时不展示“0 天波动”。
- 趋势页只显示可从记录重新计算的事实：有效样本范围、周期/经期中位数、MAD，以及流量、痛感和症状各选项的实际记录天数。
- 未填写的字段视为缺失数据，不能推断为没有流量、痛感或症状；趋势不输出因果关系、诊断或泛化健康结论。

### 经期事件与日历标记调整

- 同一天标记“月经来了”后再次标记“月经走了”，视为取消本次经期，直接删除该开放记录，不生成 1 天经期。
- 记录页移除“调整经期”及其底部面板；已完成经期只读展示，经期主操作只保留“月经来了”和“月经走了”。
- 日历日期单元为所有日期预留相同高度的顶部标记槽，开始、结束和每日记录图标统一显示在数字上方，同日多状态并排显示。
- 日历图例扩展为实际经期、预测经期、已选择、月经来了、月经走了和已记录六种状态。
- 记录列表中，已填写值使用项目强调色和较高字重，未填写值使用弱化灰色，使状态无需打开面板即可区分。
- 日历状态图标进一步改为起点旗帜、终点旗帜和记录剪贴板，并适当放大；日期数字下方增加与顶部标记槽等高的留白，消除日期单元上松下紧的问题。
- 已完成经期不再使记录页操作按钮消失；任意可选日期始终提供“月经来了”或“月经走了”。选择经期开始日点击“月经走了”会删除整段经期，选择中间日期会调整结束日，选择当前结束日再次点击会取消结束状态，以便重新选择结束日期。
- 修正月视图边缘日期的禁用判断：相邻月份中不晚于今天的日期也可直接选择，并自动切换到对应月份；未来日期继续禁用。
- 日历“月经来了 / 月经走了”标记使用播放与暂停图标；日期内的开始、结束和记录标记统一移除白色底座，在粉色经期色带上使用奶油黄 `#FFE08A`，普通日期和图例使用深赭黄。图标从色带上边缘向下留出 3px，日期单元总高度保持不变。
- 日历状态层级重新规范：实际经期保持实心莓果色带，预测经期使用更细的浅粉描边，跨周色带在每行首尾圆角收口；选中日期改为数字下方短横，不再使用灰色填充、圆形轮廓或阴影，避免遮断经期色带，并与“今天”的圆环明确区分。
